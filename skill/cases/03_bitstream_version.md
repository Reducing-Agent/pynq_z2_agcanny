# 如何判断位流新旧（最容易静默出错的一处）

## 案例 8 · 判断 bitstream 新旧的方法论

- 陷阱：XC7Z020 的 `.bit` 是**整片配置帧**，
  **同一器件无论设计怎么改都恒为 4045771 字节**。
  v4 / v5 / v8 / v8.2 / v8.2b 全部一样大 —— **文件大小完全无法判断新旧**。
- 方法：**改用 MD5 校验**；另外 `.bit` 文件头的 ASCII 里能直接读出生成日期。
- 记录：v4 `.bit` `09e0715982d6ff06ce12888a87e44275` / `.hwh` `71242f26733fce1a5994c5e248fdc6f1`；
  本项目现行 v8.2b `.bit` `6b5fd2f9…` / `.hwh` `9b7407a3…`
- 附带陷阱：**目录名 ≠ 位流版本**。位流文件就叫 `rgb2gray.bit`，不带版本号；
  板端有 `rgb2gray_v5/` 这种历史遗留目录名，里面放的可能是 v8.2b 的位流。

### 由此推出的一套规矩（照抄）

1. **位流一律取"脚本同目录"的那份**，删掉所有"本目录找不到就兜底到旧目录"的写法
   —— 宁可报错，不要静默跑错版本。
2. **加载前必须校验 MD5**（本项目 `hw_driver.py` 的 `check_bitstream_md5()`，
   `RGB2GRAY_SKIP_MD5=1` 可跳过）。
3. **每重建一次位流就重算 MD5**，并同步到三处：
   `hw_driver.py` 的 `BIT_MD5_PREFIX`、`check_kit.py` 的 `BIT_EXPECT`、`FILES.txt`。
   用 `scripts/update_bitstream.py` 一键做，不要手改。
4. **WNS 一模一样 ≠ 位流一样**：布局布线有随机性，时序报告不能当版本号用。

### 为什么这条值 15 分里的钱

本项目 10-19 真实事故：误载了 v4 位流，结果 `mode >= 3` 全部输出 EMBOSS。
**功能看起来是通的**（前 3 个模式完全正常），只有后几个模式"效果不对"——
排查了很久才想到是位流版本。没有 MD5 校验的话，这类错误可以静默活到答辩现场。

**可复用结论**：任何"二进制产物 + 多版本并存"的场景，
**版本的唯一真相源必须是内容哈希，不能是文件名、文件大小或目录名**。
