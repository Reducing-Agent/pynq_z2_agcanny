# HLS 语言与接口陷阱

五个都是"编译/综合会过、但结果不对或接口没生成"的类型，最难排查。

---

## 案例 11 · 宏定义里不能出现 `#pragma`

- 现象：`error: use of undeclared identifier 'PRELOAD_HCONV'` +
  `expected ';' after expression`，共 9 个错，C 仿真**直接编译失败**。
- 根因：把 4 段雷同的预装代码写成宏，宏体里带了 `#pragma HLS PIPELINE II=1`。
  但 **`#` 在宏定义里是"字符串化运算符"**，`#pragma` 被当成
  "把 `pragma` 这个词变成字符串"，宏定义当场被破坏 —— 等于这个宏从未定义过。
- 修复：删掉宏，手写展开 4 段；或者改用 `_Pragma("...")` 运算符。
- **自我纠错**：第一次看到 "undeclared identifier" 以为是拼写或作用域问题，
  排查方向错了。真正原因是**预处理器的语法规则，与 HLS 无关**。
- **可复用结论**：宏里要塞编译指示，只能用 `_Pragma("...")`；
  带 `#` 的预处理指令一律不能进宏体。

## 案例 12 · 一维卷积核的系数和是 16，不是 256

- 现象：Python 对拍 162 例挂了 123 例，平坦图输入 77、输出却是 **0**。
- 根因：5×5 高斯拆成两次一维卷积，核是 `[1,4,6,4,1]`，**一维求和 = 16**；
  二维 `[1,4,6,4,1]⊗[1,4,6,4,1]` 求和才是 16×16 = 256。
  可分离实现应该**每级 `>>4`**，我却两级都写了 `>>8`，等于除以 65536。
- 连带坑：**两级分别截断 ≠ 一次 `>>8`**（中间结果会被截成 8 bit），
  所以**黄金参考也必须分两步 `>>4`**，否则对拍会在有噪声的图上随机差 1。
- **可复用结论**：写可分离卷积时，"归一化移位量"要按**一维核**算，
  不是按二维核的总系数和。对拍脚本的移位量也必须和硬件**逐步一致**。

## 案例 13 · cosim 开局就段错误，但 csim 全绿

- 现象：csim **864 例全 PASS**，cosim 却一条用例都没跑到就 `SIGSEGV`
  （`CodeState = ENTER_WRAPC`），报告只显示 `Verilog | Fail | NA`。
- 根因：cosim 自动生成的 wrapper（`apatb_rgb2gray.cpp`）里写死
  `port.nbytes = { 307200 }`，即**每次调用都按 `MAX_PIXELS` 的长度 dump
  输入/输出向量，完全不看本次图像实际多大**。
  测试台按 `w×h` 分配（32×24 只有 768 字节），wrapper 却要读 307200 字节 → 越界。
- 为什么 csim 不受影响：**csim 直接调用原函数，不经过 wrapper**。
- 修复：测试台缓冲区一律按 `MAX_PIXELS` 分配；另外用 `-D__HLS_COSIM__`
  （Vitis 编译时自动加的宏）把 cosim 用例裁到 96 例，否则 RTL 仿真要跑数小时。
- **可复用结论**：csim 与 cosim 走的是**不同的代码路径**，
  "csim 过了"推不出"cosim 能过"。凡涉及数组长度，一律按 `MAX_*` 分配。

## 案例 14 · 主循环 II 卡在 2：一次"回读自己刚写的值"引发的依赖

- 现象：`csynth` 报 `II Violation: Memory Dependency`，主循环 achieved II = 2，
  吞吐直接减半（5×5 通路理论耗时从 3.07 ms 变 6.14 ms）。
- 根因：Canny 滞后的"当前行左邻是否强边"写成回读 `st[iw][xo-1]` ——
  **同一块 RAM 上一拍刚写、这一拍就读**，HLS 判成跨迭代 RAW，只能排成两拍。
- 修复两条：
  1. 左邻改用**寄存器** `prev_s`（一个 FF，每行开头清零），不再回读 RAM；
  2. 加 `#pragma HLS DEPENDENCE variable=st inter false`。
- **为什么第 ② 条是安全的而不是赌**：本轮只写 `st[iw][xo]`、只读 `st[ir][xo±1]`，
  而 `iw = (y−4)&1`、`ir = (y−5)&1`，**两者奇偶必然相反 → `ir != iw` 恒成立**，
  读写落在两块不同的 RAM 上，任意两次迭代间不存在真依赖。
  HLS 的别名分析只看到变量下标，**看不出这个下标关系**，所以必须显式声明。
- 结果：II 回到 1，LUT 只增加 197。
- **可复用结论**：写 `DEPENDENCE ... false` 之前，
  必须能把"为什么没有真依赖"用**下标关系推导**讲清楚；
  讲不清楚就说明它可能是真依赖，不该强关。

## 案例 15 · `s_axilite` 的指针出参不会生成寄存器

- 现象：想让 IP 回传一个标量 σ，写成 `int *sigma_out` +
  `#pragma HLS INTERFACE s_axilite port=sigma_out`。
  **综合、打包全过，IP 也正常生成**，但生成的头文件里**根本没有这个寄存器** ——
  寄存器表和上一版一字不差，全文搜不到 `sigma`。ARM 侧读不到，这个特性等于没做。
- 附带现象：cosim 还连续挂了两轮（`212-300` / `212-360`）。
- 修复：改用**函数返回值** + `#pragma HLS INTERFACE s_axilite port=return`，
  生成可读的 `ap_return` 寄存器。
- 代价：返回值占用 `0x10`，把 width / height / mode **整体后推一格**。
  旧驱动配新位流时，width 会写进只读的 σ（**静默无效**）、
  height 写进 width（表现为"只对上半部分生效"）—— **极难排查**。
- **可复用结论（两条）**：
  1. Vitis HLS 对 `s_axilite` 上的标量**出参**，必须用返回值或 `volatile` 引用；
     **"综合能过"不等于"接口真的生成了"**。
  2. **每轮构建后第一件事：grep 生成的 `xrgb2gray_hw.h` 里的 `ADDR_..._DATA`**，
     禁止在驱动里硬编码寄存器偏移。
