# 提示词模板 01 · 软硬件划分推导

## 适用场景

有一个算法要在 Zynq（ARM + FPGA）上实现，需要决定哪部分放 PL、哪部分放 PS，
并能说清**依据**（而不是"感觉这个适合硬件"）。

## 在本项目中的效果

导出报告 §3.1 的划分依据：**PS 管每帧一次的标量统计（AGC 增益、噪声 σ），
PL 管每像素的流式运算**。关键依据是**数据率**而非功能——
AGC 需要对全帧求均值（每帧 1 次标量），高斯滤波要对每个像素做卷积（307 200 次）。
这个划分后来被证明是对的：σ 回读让阈值能自动跟随光照，而 PL 侧不受影响。

## 提示词模板

```
我们要在 Zynq-7000（ARM Cortex-A9 @650 MHz + xc7z020）上实现下面这个算法：

【算法描述：输入是什么、输出是什么、每一步做什么】

器件约束：
- PL 逻辑资源约 53k LUT、DSP 220 个、BRAM 140 块
- PS 是双核 Cortex-A9
- PL 与 DDR 之间是 AXI3（burst 上限 16）

请按下面的顺序回答，**不要跳步**：

1. 对算法的每一步，估算它的**数据率**：
   每个像素要执行几次？每帧要执行几次？
   （例：均值滤波 = 每像素 9 次乘加；求全帧均值 = 每帧 1 次累加）

2. 按数据率给出划分建议：
   - 每像素都要做的 → PL（并行度高）
   - 每帧只做一次的标量统计 → PS（省资源，延迟不重要）
   - 需要跨像素串行拓扑的（如连通域、排序）→ 留在 PS，
     并说明硬件化是否划算

3. **给出判据**：如果上面的划分是错的，会观测到什么现象？
   （例：若把全帧均值放进 PL，会看到 BRAM 或加法树成为瓶颈、
     LUT 暴涨但吞吐没提升）

4. 指出这个划分的**边界条件**：什么情况下应该改？
   （例：分辨率降到 64×64 时，PS 逐像素也算得过来，划分就要重估）
```

## 使用说明

- 第 1 步**不能省**。直接问"这个算法该放哪"会得到"卷积适合 FPGA"这类废话。
  先量化数据率，答案自己就出来了。
- 第 3 步是防错的关键。我们有过一次跳过这步，结果把一个每帧 1 次的统计
  放进了 PL，白花了两天。

## 失效条件

- 算法里有**跨像素串行依赖**（连通域标记、霍夫变换、排序）时，
  第 2 步的"每像素 → PL"不适用，这类通常留在 PS 更划算。
- 分辨率极低（如 32×32）时，数据搬运开销可能大于计算开销，划分结论会反转。
