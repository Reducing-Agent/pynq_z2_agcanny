# 提示词工作流（Prompt Workflows）

本目录是一组在本项目中用过、能稳定完成某类任务的
提示词模板及使用说明。

本目录下每个文件是一份**在本项目中用过、产出过结论**的提示词模板。
针对 PYNQ + HLS 开发中几类高频、容易判断错误的任务，不是通用写作模板。

| 文件 | 解决什么问题 | 在本项目中的用途 |
|---|---|---|
| `01_hw_sw_partition.md` | 算法该放 PL 还是 PS | 导出报告 §3.1 的软硬件划分依据 |
| `02_report_bottleneck.md` | 从综合报告定位性能瓶颈 | 定位到「条件 DDR 写打掉 AXI burst」 |
| `03_golden_reference.md` | 造一份独立的黄金参考用于对拍 | 产出 `filters.py`，支撑 180 组逐像素对拍 |

## 怎么用

1. 找到对应场景的文件
2. 把里面的模板整段复制，按 `【】` 提示填你的实际信息
3. **关键：模板里「要求模型给出判据」那一步不要删** ——
   我们踩过的坑大多源于"模型给出的结论没有判据"，
   导致错的结论也被执行了（见 `../cases/02_performance_method.md`）

## 通用原则（三条）

1. **要判据，不要结论。** 让模型先说"什么现象会证明/证伪这个结论"，
   再决定要不要动手。本项目耗时最长的一次定位就源于跳过了这一步。
2. **先找反例证伪。** 有了候选根因，先问"有没有什么现象会推翻它"。
   σ 累加器那次就是没做这步，改了两天发现根因在别处。
3. **让模型回读源码再提建议。** 我们有过模型建议"降采样"和"每帧重载 Haar"，
   而代码里早已实现 / 根本不存在。回读源码这一步能挡掉这类空转。
