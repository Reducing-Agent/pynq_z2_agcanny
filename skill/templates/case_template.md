# 案例写作模板（大模型协作记录）

> 指南 3.3.3.1 / 3.3.5.3 要求记录"提示词 / 模型回答 / 自我纠错轨迹"。
> 本模板给软件组 & 硬件组统一格式，照抄填空即可。

---

## 标题格式

```
**案例 N · <现象概述>（含一次归因错误 / 含一次撤回）**
```

标题括号里要标出"含一次归因错误"。只写"发现问题→解决问题"是排障记录；
指南要的是**自我纠错轨迹**，即还要写出"我一开始想错了"以及证伪它的证据。

---

## 正文五段（顺序固定）

```markdown
**案例 N · <现象概述>**

- **现象**：<可观测的事实，带数字>。不要写"很慢"，写"20.57 ms"。
- **定位**：<怎么查的，用了什么对照实验>。<这一步要能复现>。
- **（建议写）第一版归因（错的）**：<我以为是 X>，据此做了 Y，
  结果 <耗时没有变化>。
- **真因 / 修复**：<原因>，改成 <具体做法>。
  附**反例**：<什么现象证伪了第一版假设>。
- **结果**：<改前 → 改后，带倍数>。代价：<资源/复杂度代价，必须写>。
- **可复用结论**：<1~3 条，脱离本项目也成立>。
```

---

## 五段的判定标准

| 段 | 及格线 | 常见不及格 |
|---|---|---|
| 现象 | 有数字、可复现 | "效果不好"、"有点慢" |
| 定位 | 说清用了什么对照实验 | 直接跳到结论，没有推理 |
| 纠错 | **明确写出错误假设 + 证伪它的证据** | 只写正确路径，不写走过的弯路 |
| 结果 | 改前→改后 + 倍数 + **代价** | 只报好消息，不报代价 |
| 结论 | 抽象成一条规则 | 只描述本项目的具体代码 |

## 反面例子 vs 正面例子

**反面示例**（只有排障轨迹）：

> 案例 · 性能优化：发现 DDR 写在 if 里导致没有 burst，
> 改成片上缓冲后性能提升到 3.258 ms。

**正面示例**：

> 案例 10 · 主循环慢 6.7 倍而综合报告说 II=1（含一次归因错误）
>
> - 现象：op 1~11 全部 20.57 ms（6.70 cyc/px），csynth 却报 II=1 全绿。
> - 第一版归因（错的）：以为是 σ 单累加器的跨迭代依赖。
>   改成 16 bank 轮换 —— 耗时没有变化，仍是 20.57 ms。
> - 反例：op 9/10/11 走 `path5x5()`，**根本没有 σ 累加**，
>   实测却一样慢。唯一变量对不上，假设被证伪。
> - 真因：两条慢通路唯一的共同点是 **DDR 写被包在 if 里**……
> - 结果：20.57 → 3.258 ms（6.31×）。**代价：4 块 RAMB18**。
> - 可复用结论：① csynth 的 II 是估计值；
>   ② 先找反例证伪自己的假设；③ m_axi 写要无条件、地址连续。
